Personal browser library

Every initiative. Every placement. One organized link library.

Your browser, your library. Data stays in this browser on this site, not in shared team storage. Clearing site data, private browsing, or browser storage eviction can remove it. Download JSON backups regularly. No sign-in or Copilot installation required.

How to use

Create a labeled link, share it, and keep an organized record. No account or Copilot installation needed.

Share the direct guide link with teammates, or copy this page address while this tab is open. It shares these instructions, not your personal library.

Each browser profile keeps its own library on this site. There is no automatic team, Excel, or SharePoint sync. Agree on campaign naming with teammates before creating links.

Create and share a link

  1. Choose or create an initiative. In Create link, choose an existing Initiative or select + New initiative. Enter an Initiative name and a unique Campaign key, then select Create initiative. The key becomes utm_campaign: keep it stable across all placements for that initiative. The Initiatives tab also lets you create groups and view their links.
  2. Name the link and choose its destination. Enter a descriptive Link name so you can find it later. Paste a trusted HTTPS address into Destination URL; any HTTPS host is supported, without credentials or nondefault ports. Learn is the default. Existing UTM values before # are replaced; unrelated query parameters and full hash routes stay intact.
  3. Choose a channel preset. Use the channel guide below to match where you will share the link. A preset fills Source (the sender or site) and Channel (the distribution method). Both stay editable. These URL labels are called UTMs; they describe a link, rather than count its clicks.
  4. Describe the placement. Optionally enter Placement, such as hero_button or booth_poster, to distinguish links in the same campaign. Under Additional details, use Term for an optional keyword or segment. A Private note is not in the URL, but it is included in CSV and JSON exports.
  5. Generate, save, and share. Review the preview, then select Generate & save link. The draft is not saved until you do this; each saved link gets a unique learn_link_id. Both the saved URL and a matching green QR code with the GitHub mark appear automatically, for every channel. Select Copy link or Download SVG. QR codes are generated locally. Scan-test before sharing or printing, keep the white border, and use a larger size for long links. If clipboard access is blocked, select and copy the displayed URL.
  6. Find and reuse your links. In Link library, search or filter by initiative and channel. Use Copy link or QR code to share again. Duplicate opens a new draft; saving it creates a new ID without changing the original. Archive hides a record from the default list, but does not disable a published URL. Check Include archived and select Restore to bring it back.

Use consistent, short labels. Campaign, Source, Channel, Placement, and Term values are lowercased; spaces become underscores (for example, Learning Path becomes learning_path). Use letters a-z, numbers, underscores, dots, or hyphens, starting with a letter or number. Never put personal information or secrets in URLs.

Choose a channel

Pick the distribution method, not just the type of destination page. You can point an Email link at a learning path, or use Learning path for a link placed inside one.

Email
Newsletters or email messages. Defaults: Source newsletter, Channel email.
QR code
Scannable posters or handouts. Defaults: Source event, Channel qr.
Event
Event communications or materials. Defaults: Source event, Channel event.
Social
Social posts. Defaults: Source linkedin, Channel social. Change Source for another platform.
Partner
Partner referrals. Defaults: Source partner, Channel referral. Change Source to a useful partner label.
Learning path
Links shared within a learning path. Defaults: Source learning_path, Channel learning_path. Change Source to describe the path if useful.

Every saved link gets a QR code, including Email, Social, Learning path, and custom channels. Channel labels describe distribution and attribution, not which outputs are available. Generating or downloading a QR code does not change the Source, Channel, other URL labels, or link ID.

Keep a backup, not just a spreadsheet

Export all CSV in Link library downloads all links, including archived links and notes, for reporting or opening in a spreadsheet. Click counts are blank. CSV is not a restorable library backup.

Use Download backup at the bottom of the page for a restorable JSON file. To preserve your library or move it to another browser, keep that file somewhere appropriate for its contents. In the other browser, open this site, select Import backup, choose the JSON file, review it, and select Merge backup. New records are added; existing records stay unchanged. Conflicting IDs are rejected without changing your library.

Back up regularly: clearing site data, private browsing, storage eviction, or losing a browser profile can remove your library. Sharing a backup shares its records and private notes; it does not set up ongoing synchronization.

Read the dashboard as inventory

Dashboard counts saved links, initiatives, and channels, including archived records. It does not report clicks, visitors, or conversions. Link clicks remain Not connected. Select View integration requirements there to learn about a separate approved analytics or redirect service.

Report attributed visits

A separately approved analytics integration would need to capture UTMs and learn_link_id at the destination, preserve attribution through sign-in, and provide authorized aggregate reporting. Attributed visits are not click counts.

Count link opens

A separately hosted, approved redirect service could record a request before sending the visitor to the destination. It would need its own privacy, access, retention, and bot-filtering controls. That service is not included here.

Existing direct links do not retroactively become tracked redirects. QR URL requests are not the same as camera recognition. Tracking remains Not connected in this tool.
